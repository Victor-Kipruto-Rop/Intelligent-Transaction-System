# Incident Response

## Severity
Define severity by customer impact, financial integrity risk, data exposure, scope and duration. Security incidents and suspected ledger corruption receive immediate escalation.

## Response lifecycle
Detect -> declare -> assign incident commander -> contain -> preserve evidence -> investigate -> recover -> reconcile -> communicate -> post-incident review.

## Financial integrity incidents
Pause affected workflows when continuing could compound harm. Preserve source payload references and audit evidence. Do not manually edit posted ledger entries. Use controlled compensating operations after approval.

## Communications
Maintain customer-facing status updates, internal stakeholder updates, regulatory/customer notification assessment and a documented timeline. Do not disclose sensitive investigation details.

## Post-incident
Publish blameless review, root cause, contributing factors, detection gaps, recovery metrics, action owners and due dates. Verify remediation.
